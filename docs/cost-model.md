## Honesty constraint (ASM-6)

No web retrieval tool was available when this model was built, so published Google Cloud list prices could not be fetched here. Every unit price below ships with a source URL and a `status`; prices marked **ASSUMPTION-UNVERIFIED** are not defensible until the implementation phase retrieves the list price and flips the status. Two facts are structural, not numeric, and are stated as verified:

- Cloud Run bills only for resources used, rounded up to the nearest 100ms, which is why idle minScale:1 CPU is a real line item.
- Gemini/Vertex bills per token with input and output priced separately, varying by model and context window.

## Dominant cost driver

The dominant cost is structural and independent of exact prices: **the always-on Cloud SQL instance plus the `minScale: 1` idle Cloud Run instance**. Both are time-billed regardless of traffic, while every other line item is volume-billed against small volumes. 2922 decisions/month is a trivially small workload; three years of 15-minute history is ~210 MB in BigQuery; evidence storage is ~6 GB. The pilot bill is set by always-on floors, not by decision volume. The two levers that matter: (a) whether `minScale: 1` is genuinely required, and (b) whether Cloud SQL can be deferred until the Postgres migration actually lands.
